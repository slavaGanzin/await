01 ec2 just booted
await — ec2 ssh

SSH keeps saying
Connection refused.

EC2 takes 30–90s to accept SSH after provisioning.
You don't know when. await knows when.

await 'test -f /tmp/.ec2-ready' \
  --cmd-timeout 3 \
  --exec 'ssh ubuntu@prod'
SSH ready check + auto-connect in one line. No polling loops.
Classic devops use case. EC2 provisioning latency is unpredictable. await solves it cleanly.
02 k8s pod is pending
await — k8s pod

Need to port-forward
once it's Running.

Pods go Pending → ContainerCreating → Running.
You need the right state, not just "it started."

await \
  'kubectl get pod app ... | grep Running' \
  --timeout 120 \
  --exec 'kubectl port-forward pod/app 8080:80'
Pipe any command through grep — if grep exits 0, condition is met.
kubectl + grep pattern. Idiomatic — any command that exits 0 is a valid condition.
03 docker stack starting
await — docker stack

postgres + redis.
nothing is ready yet.

Multiple services, each with its own startup time.
ALL must be healthy before running migrations.

await \
  'pg_isready -h localhost' \
  'redis-cli ping' \
  --exec 'python manage.py migrate && runserver'
Multiple conditions are polled in parallel. ALL must succeed before exec runs.
Multi-service readiness. N conditions checked in parallel. Clean dependency management.
04 ci is running
await — ci merge

Pushed at 6pm.
CI takes 20 min.

Close the laptop. await babysits CI for you.
Merges automatically when green.

await 'gh run view --exit-status' \
  --cmd-timeout 10 \
  --timeout 300 \
  --exec 'gh pr merge --auto --squash'
Never babysit CI again. Close the laptop, get the merge.
The CI gating pattern. Huge time saver. Works with any CI tool that has an exit-code CLI.
05 deployed to staging

Takes 2 min to

Run smoke tests only once health check passes.

await 'curl -sf staging.myapp.com/health' \

  --timeout 120 \

Health-gated smoke tests. No fixed sleeps in your deploy pipeline.
CI/CD pipeline pattern. sleep 120 is common and terrible. await is better.
06 set it and forget it
await — site monitor

Your site goes down
at 3am.

A monitor in a single tmux pane.
Fires the moment your site stops responding.

await 'curl -sf https://myapp.com' \
  --forever \
  --fail \
  --exec 'ntfy send "site is down"'
--forever restarts after exec. --fail inverts the condition. One line uptime monitor.
--fail is the inversion flag. --forever makes it run continuously. Together: poor man's alerting.
